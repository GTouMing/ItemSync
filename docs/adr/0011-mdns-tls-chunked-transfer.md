# 0011. mDNS 发现 + TLS 1.3 + 分块续传

- 状态：已接受
- 日期：2026-11-01
- 修订：Android 端需 API 29+ 才支持 TLS 1.3，见 [ADR-0027](0027-android-min-sdk-29.md)。

## 背景

局域网内节点需要自动发现、安全连接、可靠传输。没有中心服务，不能依赖 DNS 或公网 CA。

## 决策

1. **发现**：JmDNS（纯 Java，Windows 与 Android 均可运行）注册 `_itemsync._tcp.local`，TXT 记录包含 `deviceId`、`protocolVersion`、`pairingFingerprint`（仅未配对时）。发现结果只用于提示，**连接前必须校验证书指纹**。
2. **身份与加密**：每个节点自签名 X.509 证书（密钥对存平台密钥库）；配对时互相固定指纹；连接使用 TLS 1.3 双向认证（mTLS），服务端与客户端都出示证书。
3. **传输**：单条 TCP 连接上复用多个逻辑流（长度前缀帧协议）：`HELLO`（协议版本协商）、`MANIFEST_EXCHANGE`、`BLOB_GET`、`BLOB_PUT`、`ACK`。大文件按 1 MiB 分块，每块带序号与校验，支持**断点续传**与并发块窗口。
4. **端口固定**：监听 TCP `47800`，mDNS TXT 同时发布端口号（为未来迁移留余地）。端口被占用时启动失败并提示用户，**不自动漂移** —— 漂移会让防火墙规则与手动配对失效。
5. 每个 Blob 传输完成后以 SHA-256 校验；校验失败整块重传，不落盘到最终路径。
6. 协议版本不兼容时拒绝连接并提示升级，不做静默降级。

## 后果

- JmDNS 在部分 Android 厂商 ROM 上不可靠（组播被限制），需要“手动添加 IP”作为兜底入口。
- 自签证书指纹固定意味着换机/重装后必须重新配对；证书轮换需要保留旧指纹一段时间。
- 协议需要明确的版本协商与扩展位，否则第二个版本就会出现兼容地狱。
- 分块续传需要“部分文件”暂存区与超时清理。

## 备选方案

- **UDP 广播 + 自研加密握手**：完全可控，但要自己实现握手、前向保密与版本协商，风险高。
- **手动 IP**：最简单，但 IP 变动后不可用，只能作为兜底。
- **mDNS + QUIC**：多流、无队头阻塞，但 Java 端 QUIC 生态不成熟。
