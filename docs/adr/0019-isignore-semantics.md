# 0019. .isignore：同步根级、参与同步

- 状态：已接受
- 日期：2026-11-01

## 背景

需求（用户补充）要求支持 `.isignore` 忽略文件。忽略规则如果两端不一致，会出现“A 认为文件已删除、B 仍然保留”的诡异状态。

## 决策

1. 每个同步根**根目录**下可有 `.isignore`，语法兼容 `.gitignore`：`#` 注释、`/` 目录分隔、`*`/`**` 通配、结尾 `/` 表示目录、`!` 否定。
2. 只在该同步根内生效：子目录中的 `.isignore` **不**生效，也不向父目录继承。一个同步根 = 一份规则。
3. `.isignore` 文件**本身参与同步**，且不能被自身的规则忽略；规则变更作为一次普通文件变更传播，使两端规则趋同。
4. 匹配对象是**逻辑名**（ADR-0012），保证 Windows 与 Android 判定一致。
5. 被忽略的条目：不扫描、不传输、**不产生墓碑**。取消忽略后按“新增”处理，而不是“恢复删除”。
6. 规则在扫描阶段应用（早期过滤），同时在应用阶段二次校验，防止规则与文件在同一运行中变化。

## 后果

- 需要共享层实现一个 gitignore 兼容的 glob 引擎，并配套大量边界用例（`**/`、否定、锚定、尾斜杠）。
- 规则文件本身冲突（两端同时修改）走 ADR-0004 的冲突副本流程，用户可能因此产生两份 `.isignore`，UI 需明确提示“忽略规则存在冲突”。
- 重要的共享目录（如 `.git`）默认忽略，提供内置默认模板。
- 忽略规则**不**作用于版本库中的历史版本，历史仍可恢复。

## 备选方案

- **本地私有、不传输**：灵活，但两端视图会分叉，故障难排查。
- **多级继承（类 git）**：最灵活，但规则会在同步过程中变化，调试成本高。
- **只存数据库**：统一管理，但无法随目录迁移，违背用户习惯。
