# 0013. 节点密钥库自动解锁，登录只解锁 UI

- 状态：已接受
- 日期：2026-11-01

## 背景

ADR-0006/0007 要求开机自启并立即进入运行态，而 ADR-0001 要求账密登录。开机时无人输入口令，二者直接冲突。若坚持“登录后才能同步”，定时同步在无人值守时将永远不执行。

## 决策

1. 首次登录成功后生成 32 字节**节点解锁密钥（Node Unlock Key, NUK）**，用平台密钥库封装后持久化：
   - Windows：DPAPI（`CryptProtectData`，CurrentUser 范围）。
   - Android：Android Keystore 中不可导出的 AES-GCM 密钥加密后存 `EncryptedSharedPreferences` 或私有文件。
2. 自启动时节点用 NUK 自动解锁：解开数据库主密钥、加载 TLS 私钥句柄，进入运行态，无需人工输入口令。
3. 账号口令（Argon2id 哈希）只在以下场景校验：打开主界面（可配会话 TTL，默认 15 分钟）、修改安全设置、管理与撤销邻居、执行版本回滚等破坏性操作。
4. 用户可在设置中关闭“开机自动解锁”，此时节点自启但处于锁定态，不发起同步。
5. 删除账号/重置时清除 NUK 与密钥库条目。

## 后果

- 威胁模型明确为“**设备已解锁即视为可信**”，不防御拿到已登录系统会话的攻击者。文档必须写清楚。
- DPAPI 绑定 Windows 用户配置：把数据目录拷到另一台机器无法解密，需重新登录并重新封装。
- Android Keystore 在系统备份恢复、应用重装后可能失效，需要“NUK 失效 → 回退到口令登录并重新封装”的恢复路径。
- 忘记口令且 NUK 失效 = 数据不可恢复；需在首次登录时提供恢复码并要求用户保存。

## 备选方案

- **登录后才同步**：最安全，但开机自启与定时同步形同虚设。
- **可选免密开关**：把安全责任推给用户，且默认路径仍然要选一个。
- **PIN/生物识别**：体验好，但偏离“账密登录”的需求，可作为后续叠加能力。
