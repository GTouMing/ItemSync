# 0029. 组 ID 是命名空间，不是入组凭据

- 状态：已接受
- 日期：2026-11-02
- 修订：[ADR-0035](0035-multi-group-single-root.md) 组升级为持久化实体；组 ID 仍为发现命名空间，但不可变并作为唯一根键。
- 替代：[ADR-0024](0024-open-join-group-id-consent.md)；修订 [ADR-0021](0021-sync-group-version-vectors.md) 的组与成员部分。

## 背景

ADR-0024 把 8 位组 ID 当成唯一的入组凭据，并配套限流、轮换与黑名单。需求方澄清：组 ID 一般随机生成、可以手动修改；同一局域网内同 ID 即同组；它只决定“会和哪些局域网设备同步”。因此组 ID 不是秘密，也不能承担认证职责。

## 决策

1. 组 ID 是 8 位 `[0-9a-z]` 串，随机生成或手动修改；输入时归一为小写并校验格式。
2. 同一局域网内，组 ID 相同的设备属于同一个同步组。成员资格是隐式、动态的：没有成员表、邀请、入组审批或中心服务。
3. 组 ID 是发现命名空间，不是秘密，不用于加密、认证或权限判断。取消“组 ID 轮换”和“黑名单”作为安全机制；不再把组 ID 当作门票或密码学凭据。
4. 设备通过 mDNS 发现同组节点；能不能同步由成对信任开关决定，而不是由组 ID 决定（ADR-0030）。
5. 修改组 ID：立即停止与旧组同步；本地清除旧组的信任记录与固定证书；本地文件与版本历史保留；新组内设备默认未信任。重新输入旧 ID 也视为新组，需要重新信任与配对。
6. 只持久化当前组 ID、信任记录与固定证书；不持久化成员表。ADR-0021 的项级版本向量、墓碑、冲突与同步根语义继续有效。

## 后果

- 知道组 ID 的人可以看到同组设备的在线状态与设备名，但不能读取文件；这是明确接受的产品取舍。
- 组 ID 只有 8 位，可能碰撞；手动输入需要 UI 提示“同 ID 即同组”，不能宣称安全。
- 没有成员审计与成员历史；信任开关是唯一持久化的对端关系。
- 组 ID 泄露不需要“轮换”补救；关闭信任或撤销节点即可阻断同步，必要时换 ID 离开旧组。

## 备选方案

- **保留入组门票模型**：需要限流、轮换、黑名单与“不得泄露”的文案，和“同 ID 即同组”的体验冲突，否决。
- **成员表 + 入组审批**：更可控，但需求方明确不要审批流程，否决。
- **16 位秘密组 ID**：更安全，但用户要求可手动输入、一般随机；长 ID 的体验成本高，否决。
- **组 ID 即组密钥**：8 位熵严重不足，否决。
