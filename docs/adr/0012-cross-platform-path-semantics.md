# 0012. 跨平台路径语义：可逆转义 + 碰撞改名

- 状态：已接受
- 日期：2026-11-01

## 背景

两端文件系统语义不同：
- Windows/NTFS：大小写不敏感但保留大小写；禁止 `\ / : * ? " < > |`；保留名 `CON`、`PRN`、`AUX`、`NUL`、`COM1..9`、`LPT1..9`；不允许结尾的空格与点；默认路径上限 260 字符。
- Android（ext4/f2fs）：大小写敏感；只禁止 `/` 与 `\0`；路径长度上限远大于 Windows。

如果直接把 Android 的文件名同步到 Windows，会出现覆盖、创建失败或静默丢失。

## 决策

1. 引入**同步逻辑名（logical name）**：数据库中每个 Item 存逻辑相对路径，物理路径由 `PathCodec` 按目标平台编码得到。
2. Windows 目标端的编码规则（可逆）：
   - 非法字符与保留名用百分号转义：`:` → `%3A`，`CON` → `%43%4F%4E`（或 `CON%20`，实现时统一选一种并在编码表里固定）。
   - 结尾的空格/点追加 `%2E`。
   - 编码前若字面量本身含 `%`，先转义为 `%25`，保证可逆。
3. **大小写碰撞**：同一目录下逻辑名仅大小写不同的多个 Item（`Foo.txt` 与 `foo.txt`），同步到 Windows 时为后到的那个生成冲突副本，UI 标记为“大小写冲突”，不覆盖。
4. **超长路径**：Windows 写入统一使用 `\\?\` 前缀（UNC 为 `\\?\UNC\`），绕开 MAX_PATH；单段文件名超过 255 字节仍然报错。
5. 编码不可逆或无法表示时（如超长单段名），列入“无法同步”清单并在 UI 展示原因，不静默跳过。

## 后果

- Windows 上用户看到的是转义后的文件名（`a%3Ab.txt` 而不是 `a:b.txt`），需要 UI 提示“原名是什么”。
- 逻辑名与物理名的映射必须持久化，否则改名/迁移会重复创建文件。
- 保留字表与非法字符表要跟着 Windows 版本演进维护。
- 大小写碰撞检测需要按目录做规范化索引，扫描时额外一次比较。

## 备选方案

- **报错跳过**：最诚实，但用户会面对一堆“同步失败”却不知如何修复。
- **限制文件名**：预检拒绝，简单但把负担全推给用户。
- **不处理**：必然静默丢文件，不可接受。
