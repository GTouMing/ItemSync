# 0022. 同步根允许嵌套但强警告

- 状态：已接受
- 日期：2026-11-01

## 背景

用户可能把 `C:\Docs` 放在同步组 A，又把 `C:\Docs\Sub` 单独放进同步组 B。两个引擎会同时接管同一批文件。

## 决策

1. 添加同步根时做**预检**：
   - 完全重叠（同一路径）→ 直接拒绝。
   - 父子嵌套 → 允许，但弹出强警告，说明“该目录会被两个同步组同时接管，可能产生冲突副本”，并要求显式确认。
2. 确认后记录覆盖关系，UI 在同步根列表上标记“被 X 覆盖”。
3. 运行时不阻止两个引擎工作，冲突由 ADR-0004 的冲突副本机制兜底，不静默丢数据。
4. 诊断包中包含覆盖关系，便于排查。

## 后果

- 用户可获得“整体同步 + 子目录额外同步到另一台设备”的灵活性，代价是潜在重复传输与冲突副本。
- 需要一次目录树包含关系检查（规范化路径后比较），注意大小写与符号链接。
- 若未来要自动排除，需改为“后加者优先”的隐式规则，属于新 ADR。

## 备选方案

- **禁止嵌套**：模型最干净，但用户会撞墙。
- **自动排除**：无需用户理解，但隐式行为极难调试。
- **不检查**：两个引擎抢文件，最坏情况丢数据。
