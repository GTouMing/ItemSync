# 0025. 单本机账号，无应用内角色

- 状态：被替代（ADR-0028 本机密码）
- 日期：2026-11-01

## 背景

需求中的“权限管理”主要指系统层面的开机自启动、文件夹访问、后台保活。需要确认是否还要应用内的多账号与 RBAC。

## 决策

1. 一台设备只有**一个本机账号**，首次运行创建，之后只用于解锁 UI 与破坏性操作校验（ADR-0013）。
2. **不做**应用内角色（管理员/访客/只读），不做组内 RBAC。
3. “权限管理”清单固定为操作系统权限：
   - Windows：目录读写权限、用户级自启（HKCU Run）、托盘常驻。
   - Android：`MANAGE_EXTERNAL_STORAGE`、`POST_NOTIFICATIONS`、`SCHEDULE_EXACT_ALARM`/`USE_EXACT_ALARM`、`RECEIVE_BOOT_COMPLETED`、电池优化白名单。
4. 组内治理只有两种动作：**共享同意**（双向）与**黑名单/移除**。

## 后果

- 多人共用一台电脑需要各自安装或使用不同 Windows 用户账户（DPAPI 本身按用户隔离）。
- 审计日志无法回答“是谁点的”，只能回答“本节点的哪个会话”。
- 若未来要多账号，需要重做密钥库封装、配置隔离与自启注册，属于新 ADR。

## 备选方案

- **多本机账号**：适合共用电脑，但数据目录、密钥库、自启都要按用户隔离。
- **单账号 + 角色**：单一账号下角色没有意义。
- **组内 RBAC**：对等设备模型下无处施力。
