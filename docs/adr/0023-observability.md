# 0023. 结构化日志 + 运行历史 + 诊断包

- 状态：已接受
- 日期：2026-11-01

## 背景

同步故障几乎只在真实环境重现（权限、断电、厂商 ROM、路径编码）。用户报障时，如果只有一句“同步失败”，无法定位。

## 决策

1. **结构化日志**：JSON Lines，按天滚动，默认保留 7 天，级别可配。字段固定：`ts`、`level`、`node`、`group`、`runId`、`item`、`event`、`durationMs`、`errorCode`。
2. **运行历史**：每次 Sync Run 记录开始/结束时间、触发来源、扫描项数、传输字节、冲突数、错误码；保留最近 200 次，可按同步组筛选。
3. **诊断包**：一键导出 zip，内容为：脱敏配置、最近日志、同步根清单摘要（不含文件内容）、冲突列表、版本库统计、平台能力信息。**不含**口令、私钥、文件内容、完整路径（可配置是否含）。
4. 错误码体系在共享层统一定义（如 `PATH_ENCODE_FAILED`、`BLOB_HASH_MISMATCH`、`PEER_UNREACHABLE`），UI 与日志共用同一套码，便于用户搜索。
5. CLI 的 `log` 与 `diag` 命令直接消费同一套输出。

## 后果

- 日志写入不能阻塞同步主流程：异步队列 + 丢弃策略（队列满时丢弃 DEBUG）。
- 诊断包脱敏需要一份明确的字段白名单，避免误带路径泄露隐私。
- 错误码一旦发布不可复用，需维护枚举与文档。

## 备选方案

- **仅文本日志**：实现最简，用户报障只能靠猜。
- **日志 + Prometheus 指标**：对家用场景过重。
- **不做可观测性**：不可接受。
