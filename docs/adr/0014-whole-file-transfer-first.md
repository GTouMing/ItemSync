# 0014. 第一期整文件传输，不做块级差分

- 状态：已接受
- 日期：2026-11-01

## 背景

两个节点间传一个大文件，只改了少量字节时，是否用 rsync 式滚动校验和只传变化块。

## 决策

1. 传输单位为**整文件**，按 1 MiB 分块、断点续传、逐块与整体 SHA-256 校验（见 ADR-0011）。
2. 跨文件的内容去重由 Blob 存储天然提供：内容未变的文件根本不会进入传输。
3. 协议保留能力位：`HELLO` 中声明 `delta_supported=false`，消息类型预留 `BLOCK_HASH_REQUEST` / `BLOCK_HASH_RESPONSE`，第一期不发送。
4. 未来加块级差分时，只需在 `BLOB_GET` 前插入一轮块哈希协商，不改变帧协议与状态机。

## 后果

- 大文件小改（如虚拟机镜像、数据库转储）会整文件重传。局域网千兆环境下可接受，但 UI 需展示进度与预计剩余。
- 每文件需要暂存区与续传记录，超时清理策略必须明确（默认 24h）。
- 带宽峰值集中在局域网空闲时段需靠触发器配置规避（如限定夜间同步）。

## 备选方案

- **块级差分**：省带宽，但要维护 base 块索引、实现滚动校验和、处理块边界与并发写入，工程量与缺陷面都大。
- **阈值自适应**：小文件整传、大文件走差分，两条代码路径都要测。
- **只靠 Blob 去重**：等于本决策，但去重发生在文件级，无法解决“同一文件微改”。
