# 0008. 第三方应用启停监听仅 Windows 提供

- 状态：已接受
- 日期：2026-11-01

## 背景

“计划同步”的一个条件源是“某个应用启动前/后”。该条件在两端可行性完全不同：
- Windows：可枚举进程（`CreateToolhelp32Snapshot` 轮询、WMI 事件或 ETW），合法且无需特殊权限。
- Android：检测第三方应用启动需要 `UsageStatsManager`（`PACKAGE_USAGE_STATS` 特殊权限，商店审核敏感）或无障碍服务（高风险，易被判滥用）。

## 决策

1. Windows 端实现 `AppStarted` / `AppStopped` 条件源：按进程名/可执行文件路径匹配，轮询间隔可配（默认 2s）。
2. “启动前”只能近似：无法在目标进程启动之前插入同步。实现为“检测到目标进程出现后立即同步”，若用户需要同步就绪，可配置为“目标进程启动前先做一次快照（用于冲突判定）”。
3. Android 端**不提供**该条件源，只提供 `DirectoryChanged` 与闹钟。
4. 平台能力矩阵在共享层声明（`PlatformCapability`），UI 按能力渲染，未实现的条件不出现在选项里，避免假支持。

## 后果

- 两端功能不完全对等，文档与设置界面必须明确标注“(仅 Windows)”。
- 轮询有 CPU 开销，需要自适应间隔与“窗口最小化时降频”。
- 若后续确实要在 Android 支持，需单独 ADR 并评估商店风险。

## 备选方案

- **两端都做**：Android 需特殊权限，审核风险高，第一期不冒这个险。
- **完全去掉应用启停条件**：丢失用户明确提出的需求。
- **改为监听本软件自身启停**：用户已否认这一解释。
