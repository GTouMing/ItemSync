# 0030. 成对信任开关、短码配对与组内在线可见

- 状态：已接受
- 日期：2026-11-02
- 修订：[ADR-0033](0033-trust-without-short-code.md) 替代短码配对部分。
- 修订：[ADR-0035](0035-multi-group-single-root.md) 组内设备列表持久化；信任仍按 `(组 ID, 证书指纹)`。
- 替代：[ADR-0021](0021-sync-group-version-vectors.md) 的成员同意部分、[ADR-0024](0024-open-join-group-id-consent.md) 的共享同意与可见性部分；修订 [ADR-0001](0001-local-account-and-pairing.md) 的配对流程。

## 背景

组 ID 改为命名空间后（ADR-0029），同 ID 设备会自动发现，但组 ID 不是秘密。需求方要求：信任开关属于组信息；同步双方任意一方关闭都无法再同步；新加入组的设备对已有设备默认不信任；组内设备在线状态相互暴露。

这要求把“组 ID = 可同步”改成“组 ID = 可发现，成对信任 = 可同步”。

## 决策

1. 信任记录按 `(组 ID, 对端设备)` 保存。新设备对每个已有设备默认关闭；已有设备对新设备也默认关闭。双方都打开才同步；任一方关闭立即停止。没有组级总开关。
2. 关闭信任开关是“暂停”：保留信任记录与固定证书，重新打开即可恢复。撤销是更强的动作：删除记录与证书，再次同步需要重新配对。
3. 同组设备通过 mDNS 发现。双方都打开信任后，交换自签证书指纹，各自显示一个由双方指纹导出的 6 位短码；两台设备确认短码一致后固定证书，进入 mTLS。不做静默 TOFU，不把组 ID 当 PSK；确认前不交换文件数据。
4. 在线状态对同组设备相互可见，包括未信任设备：显示设备名、设备 ID、在线/离线、最近在线时间与信任状态（未信任/已信任/已暂停）。不显示同步根、文件名、文件内容；IP 只在详情中展示。
5. 新设备首次出现时，双方列表都标记“未信任”；任何一侧也可以主动发起配对。只有双方确认短码后，信任才生效。
6. 修改组 ID（ADR-0029）或撤销节点都会清除对应的信任记录与固定证书；重新加入需要重新配对。暂停信任不清除记录。
7. 在线状态不代表可同步；信任关闭的设备仍显示为“已暂停”，以便区分暂停与离线。

## 后果

- 组 ID 泄露只暴露在线元数据，不能直接同步文件；数据仍由成对信任与证书固定保护。
- 新设备需要双方人工确认一次，加入成本比“同 ID 自动同步”高，这是安全取舍。
- 6 位短码用于抵抗同一局域网内的中间人；确认界面必须同时展示短码与设备名。
- 成对信任状态在成员 ≤10 的规模下可接受；更大规模需要新的压缩或分组信任模型。
- “共享同意”“黑名单”“成员表”等旧术语退役，统一使用“信任开关”“撤销”“信任邻居”。

## 备选方案

- **组级总信任开关**：实现简单，但组 ID 泄露即可让陌生设备同步，否决。
- **静默 TOFU**：首次自动固定证书，易被局域网中间人利用，否决。
- **组 ID 作为 PSK**：8 位熵不足，且与“组 ID 只是命名空间”冲突，否决。
- **二维码配对**：更强，但需要额外 UI 与摄像头权限；第一期用短码，后续可叠加。
