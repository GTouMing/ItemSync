# 0026. 第一期明确不做的事

- 状态：已接受
- 日期：2026-11-01

## 背景

去中心化文件同步极易范围蔓延。把“不做”写下来，等于给实现期一个拒绝需求的依据。

## 决策

第一期（M0–M2）**不做**下列事项；需要时另立 ADR，禁止在实现中偷偷加入。

| 不做 | 原因 | 替代 |
| --- | --- | --- |
| 块级差分（rsync 式） | 工程量大、正确性风险高 | 整文件传输 + 分块续传（ADR-0014） |
| 符号链接、交接点 | 两端语义与安全风险不一 | 跳过并在“无法同步”清单中展示 |
| ACL / 属主 / xattr / 可执行位 | Android 上大多不可用 | 只保留 mtime（秒级）与目录结构 |
| 公网传输 / NAT 穿透 / 中继 | 引入服务端与安全模型变更 | 仅限局域网（含 VPN 局域网） |
| 跨节点版本历史 | 元数据传播复杂 | 版本仅在本地，可导入导出 |
| Web UI / 移动端以外的前端 | 非核心 | 桌面 JavaFX + Android 原生 |
| 多本机账号 / RBAC | 见 ADR-0025 | 单账号 |
| iOS / macOS / Linux 桌面 | 先聚焦 Windows + Android | 核心保持可移植，未来可扩展 |
| 文本三方合并 | 需要 base 内容与合并器 | 冲突副本（ADR-0004） |
| 目录级共享授权 | 需要子目录策略表 | 组级 + 成员双向同意 |
| 自动更新 / 增量升级 | 需要签名与分发通道 | 手动安装包；后续新 ADR |
| 应用级磁盘加密 | 性能与依赖代价 | 依赖系统全盘加密（ADR-0018） |

## 后果

- 这些需求出现时，标准答复是“见 ADR-0026”，并评估是否新立 ADR。
- 核心层不得为这些能力预埋抽象（避免过度设计）；只在明显会被复用的位置保留扩展位（如协议能力位）。

## 备选方案

- **不写范围外清单**：范围会以“顺便加一下”的方式失控。
- **写死到路线图**：过于僵硬，反而不如按 ADR 决策。
