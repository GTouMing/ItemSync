# 0035. 多组持久化、单根与组内设备/规则

- 状态：已接受
- 日期：2026-11-03
- 替代：[ADR-0022](0022-nested-sync-roots.md)（嵌套根）
- 修订：[ADR-0009](0009-metadata-store-sqlite-dual-impl.md)（schema）、[ADR-0017](0017-scale-targets.md)（组/根解释）、[ADR-0021](0021-sync-group-version-vectors.md)（run 作用域）、[ADR-0029](0029-group-id-namespace.md)（持久化组）、[ADR-0030](0030-pairwise-trust-and-presence.md)（设备列表/在线状态）、[ADR-0032](0032-incremental-manifest-change-log.md)（root_id → group_id）、[ADR-0033](0033-trust-without-short-code.md)（信任按组）。
- 传输层见 [ADR-0036](0036-shared-port-group-routing.md)。

## 背景

当前代码和配置仍是单组单根：`SyncNode`、`SyncEngine`、`TriggerEngine` 都把 `GroupId` 和 `SyncRootId` 作为固定构造参数，桌面/Android 配置也只有一组 `root`/`group`/`root-id`。但领域模型和数据库 schema 已经具备多组、多根的基础：`sync_group`、`sync_root`、`trigger`、`sync_run` 都带 `group_id`/`root_id`，`item_change`/`sync_cursor` 也按根隔离。

需求方要求：初始空列表，按需添加同步组；每组包含一个同步根、同步规则（闹钟/条件）和设备选择信任列表。为了降低模型复杂度，明确“一组一根”，并彻底移除独立的根 ID。

## 决策

1. **持久化组**：每台设备维护一个持久化的组列表，初始为空，最多 5 个活跃组。每个组有本地组名（仅本机显示，不跨设备同步）、组 ID、一个同步根、若干同步规则和组内设备列表。
2. **组 ID 是发现键和唯一根键**：组 ID 为 8 位 `[0-9a-z]`，创建时随机生成或加入时输入；创建后不可原地修改。组 ID 同时唯一标识该组的本地同步根；移除 `SyncRootId`，DB/协议统一使用 `group_id`。换组 ID 的唯一方式是删除旧组（保留本地文件）后新建组。
3. **一组一根**：每个组恰好一个同步根；同步根是组内的值对象（物理路径、显示名、`.isignore` 快照），不再有独立实体或独立根 ID。`sync_root` 表合并进 `sync_group`。
4. **跨组根重叠禁止**：同一物理目录不能出现在两个组中，一个组的根也不能位于另一个组的根之内。需要同一目录的多套规则时，放在同一组内配多条同步规则；ADR-0022 的嵌套根允许被替代。
5. **组内设备列表持久化**：设备列表按 `(组 ID, 设备 ID)` 保存，包含设备名、设备 ID、最近在线、当前证书指纹和信任状态；离线设备仍显示。首次发现自动加入；取消信任只关闭信任开关，“移除设备”才删除该组设备行、信任记录和固定证书并关闭该组连接。同一设备在多个组各有独立记录和信任。
6. **信任按组独立**：沿用 `(组 ID, 对端证书指纹)` 的成对开关；双方都开启才同步，任一方关闭立即停止；同一设备在 A 组信任不代表 B 组信任。
7. **同步规则属于组**：一个组可有零条或多条规则，闹钟规则和条件规则可并存，同类型也可多条；新组默认没有自动规则，仅手动同步。组内规则共享默认 30 秒防抖；组内同一时刻只跑一次同步；多条规则重叠触发时合并为“当前运行结束后最多再跑一次”，不丢弃最后一次事件。
8. **组间并发**：不同组可以并行同步；全局并发上限默认 2 个组，手动同步也进入同一队列。
9. **空列表与网络**：初始没有组时，只保留本机身份、设置和 UI，不广播任何组、不启动组同步。添加第一个组后才为该组启动发现/同步；停用组会停止该组的发现、同步和连接，但保留配置、信任和本地根。
10. **创建与加入**：创建组 = 本机生成组 ID + 本地组名 + 选择本地根 + 配置规则；加入组 = 输入相同组 ID + 选择自己的本地根。组名仅本地；信任仍由双方在组内设备列表分别开启；不做邀请或服务端成员表。
11. **根路径变更**：允许原地修改，但需二次确认；暂停该组，清空该组的 `item`/`version`/`conflict`/`sync_cursor`/`item_change`/`sync_run` 等同步元数据并重新扫描新路径；保留组 ID、信任和规则，旧路径文件不动，远端下次按全量处理。
12. **根不可用**：根目录缺失或不可读时，该组进入错误状态：停止同步、保留发现/信任/配置、在组列表显示错误，路径恢复后自动重试，不自动删除组。
13. **组生命周期**：支持启用/停用、改名（仅本地）、删除；删除需二次确认，移除该组配置、信任、规则、游标、组元数据和版本历史，但保留本地根目录文件；其他组不受影响。
14. **迁移**：已有单组单根配置自动迁移为第一个组，保留组 ID、根路径、规则、该组信任和 DB 数据；全新安装从空列表开始。Android 现有固定 `intervalSeconds` 不是闹钟规则，迁移时停用自动间隔、组变为手动并提示用户配置闹钟/条件规则。
15. **数据迁移**：`item`/`item_change`/`sync_cursor` 增加 `group_id` 并回填现有 `root_id` 对应的组；`trigger`/`sync_run` 删除 `root_id`；`sync_root` 合并进 `sync_group`；删除旧根键。`version`/`conflict` 通过 `item_id` 间接归属组。迁移要覆盖桌面触发器、Android 现有数据和契约测试里的多组/多根夹具。
16. **列表展示**：组列表显示组名、组 ID（可复制）、根路径、启用状态、规则数、设备数、最近同步状态/错误；按创建顺序排序，v1 不做手动拖拽。空列表显示“添加同步组”主操作，不默认创建组。
17. **规模**：最多 5 个活跃组；设备/项/文件规模沿用 ADR-0017，组内设备上限按现有“10 台设备”解释；组间同步并发默认 2。

## 后果

- 这是一次 large migration：配置、DB schema、协议帧、同步引擎、触发器、桌面/Android UI 都要从“单组单根”改成“多组单根、组 ID 为键”。
- 根 ID 被移除后，旧客户端/旧数据库不能直接互通；需要显式迁移，并接受一次全量重扫/重同步。
- 一组一根放弃了“同一组多根”的灵活性；跨组重叠被禁止，用户需要把同目录的多套规则放进同一组。
- 组 ID 不可变；删除组会删除该组版本历史（本地文件保留），这是需要明确告知的破坏性操作。
- 信任仍是成对开关，不存在组级总开关；组 ID 仍不是入组凭据。
- 传输层改为共享端口/组路由，细节见 ADR-0036；旧版本必须同步升级。

## 备选方案

- **保持隐式组、不持久化**：实现最小，但无法支持空列表、按需添加、组级规则/设备列表，否决。
- **一组多根**：更灵活，但会让规则/信任/根 ID/迁移复杂度翻倍；需求方明确一组一根，否决。
- **保留独立根 ID**：用户需要额外输入/分发一个 ID，且一组一根下没有独立身份，否决。
- **允许跨组嵌套根**：两个引擎会写同一棵树，冲突和重复版本风险高，否决。
- **全局设备信任**：一次信任在所有组生效，无法做到 A 组信任、B 组不信任，否决。
- **组 ID 可原地修改**：要重写所有 `group_id`、游标、信任、mDNS 和远端配对，风险和成本不划算，否决。
