# 0001. 本机账号 + 配对授权，不设中心

- 状态：被替代（本机密码见 ADR-0028；配对见 ADR-0030）
- 日期：2026-11-01

## 背景

需求要求“去中心化”和“账密登录”同时成立。若账号需要在整个局域网内统一校验，就必须有一个权威，去中心化即刻破功。

## 决策

1. 账号是**本机账号**：只存在于某一台设备，用户名 + 口令，口令以 Argon2id（随机盐、可调参数）哈希后存本地，明文永不落盘、永不传输。
2. 设备间信任通过**配对**建立：在短时窗口内交换自签名设备证书，双方展示证书指纹供人工核对，确认后互相固定（certificate pinning）。
3. 配对完成后，节点间通信**只认证书**，不再传输口令。登录只用于解锁本机 UI 与本地密钥库。
4. 撤销信任 = 从信任邻居列表删除证书，立即生效。

## 后果

- 换设备无法漫游登录，需在新设备建账号并重新配对。这是有意的取舍。
- 设备被物理控制时口令可被离线爆破 → 必须使用强哈希参数，且私钥存平台密钥库（Windows DPAPI / Android Keystore），不用自研加密。
- 账号与设备绑定，因此“多用户共用一台电脑”需要显式的多账号支持，暂不在第一期。

## 备选方案

- **集群共享账号**：首次配对时把盐与哈希复制到全网。改密码需全网传播，任一设备失守即全网失守。
- **可选中心节点**：体验最好，但不再是纯去中心化，且多一个部署物。
- **不要账号，仅共享密钥**：最简单，但失去“用户”概念，权限管理与审计无从谈起。
