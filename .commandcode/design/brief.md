# ItemSync 设计简报

> 本文件是项目的设计宪法，供后续 `/design` 命令直接使用。
> 事实来源：`README.md`、`docs/design.md`、`docs/glossary.md`、`CONTRIBUTING.md`、`desktop/` 与 `android/` 源码。
> 最后更新：2026-11-04。

## 1. Register

**Product。** ItemSync 是工具型界面，不是品牌页。界面要在每天重复使用时保持稳定、快速、可预测，而不是在首次访问时制造情绪。

注册判断依据：主窗口是操作台（状态、同步、信任、冲突、版本），不是营销、作品集或长文阅读面。Android 端是同一产品的过渡实现，规则相同。

## 2. 用户与场景

- **主要用户**：使用中文、愿意自己配置局域网同步的技术型用户。典型场景是 2 到 4 台自有设备，不信任云盘，或需要离线局域网内互传。
- **主要压力**：文件覆盖或丢失的风险；设备发现失败；信任状态不清楚；冲突不知道如何收场；多组同步根互相干扰。
- **使用环境**：Windows 桌面为主（托盘常驻，窗口偶尔打开）；Android 为辅助端（前台服务，发现与信任尚未真机验证）。二者常在同一局域网内配对。
- **不是**：企业管理员、普通办公用户、需要公网穿透或账号体系的用户。

## 3. 产品目的与硬约束

局域网内、去中心化、跨 Windows/Android 的双向文件同步，带版本历史、冲突副本与成对信任。

设计必须与这些事实一致：

- 无中心服务器，节点对等；不承诺公网穿透或云端中继。
- 每台设备最多 5 个同步组，每组恰好一个同步根；组 ID 创建后不可改。
- 规模上限：10 万项、单文件 10 GB、10 台设备。
- 同步不能代替备份，界面不能暗示“已同步就等于安全”。
- Windows 桌面优先；Android 发现、在线状态与信任已接入代码但未完成真机验证，文案不得写成已通过。

## 4. 声音与文案

- **直接、具体、克制。** 先说结果，再说后果和下一步。不写营销句、不承诺、不卖萌、不用感叹号。
- **只陈述确实知道的事。** “本机已开启信任（等待对方确认）”不能写成“双方已信任”；已建立的连接也不能升级成“可同步”。过度声明和保守到失真都是缺陷。
- **一个按钮一个动词。** 用“立即同步”“添加同步组”“删除此组”“接受远端”“恢复此版本”。不用“确定”“OK”“是”单独承担动作含义。
- **错误是恢复路径。** 说明什么失败、影响什么、下一步做什么。不把用户写成过错方，不贴未处理的异常文本。
- **状态用人的语言。** 不把枚举、错误码或 JSON 直接放进主状态区。原始诊断信息放进 tooltip、日志或诊断包。
- **中文界面，术语以 `docs/glossary.md` 为唯一来源。** 设备、节点、同步组、同步根、组内设备列表、信任开关、冲突、冲突副本、版本、回滚、配对状态等词不得混用同义词。新增用户可见术语先补术语表。
- **标点。** 中文正文用中文标点；代码、路径、命令、协议名保持原文；避免长破折号。

## 5. 反参考

不要做成：

- 通用 SaaS 仪表盘：居中 hero、三张同构卡片、胶囊按钮、渐变标题。
- 深色终端或“黑客工具”审美：霓虹绿、等宽大标题、扫描线、装饰性网格。
- 游戏化引导：庆祝动画、徽章、进度条填充情绪。
- 图标-only 工具栏、悬浮操作按钮、只能靠 hover 发现的操作。
- 用占位符当标签、用 toast 承载唯一错误信息、用颜色单独表达状态。
- 假装进度、假装在线、假装已验证；“加载中…”这类不说明工作的文案。
- 把 Windows 应用做成 macOS/iOS 皮肤，或把 Material 组件硬套到 JavaFX 上。遵循各自平台的控件行为。

## 6. 设计原则

1. **信任是产品本身。** 每个界面都要能回答：我在哪个组、根目录是什么、对端是谁、信任到哪一步、上次运行发生了什么。
2. **一个组在焦点。** 同步组是导航对象，不是表单字段。主窗口只呈现当前组，切换组不应刷新整页。
3. **主操作唯一，危险操作分离。** 主按钮只有一个；删除组、撤销信任、接受远端等破坏性动作要与安全动作分开，并说明不可逆性。
4. **状态优先于装饰。** 空闲、扫描、规划、传输、应用、回推、完成、失败、取消、离线、停用、未信任都应有明确表达，且不混淆“已连接”“已信任”“可同步”。
5. **技术信息可扫读。** 组 ID、同步根、证书指纹、端口、设备 ID 是诊断证据，必须可见、可复制、可换行，不截断关键部分。
6. **平台能力诚实。** Windows 与 Android 的可用能力不同；不支持的项禁用并解释原因，不假装存在。
7. **默认值可救。** 只有在不可逆时才要求确认；可逆动作优先提供撤销或回退路径。默认按钮永远不是破坏性操作。
8. **不让用户走进死路。** 空、错、离线、权限缺失、需要重启，都要给出下一步，而不是只显示空白或灰按钮。

## 7. 可访问性底线

- 每个可操作控件都有可访问名称。表单必须“可见标签 + `labelFor` + 可访问文本”，确认密码单独命名；占位符不得代替标签。
- 键盘可完成全部流程：Tab 顺序符合视觉顺序，焦点环清晰可见，不得 `outline: none` 且无替代。
- 对话框打开时把焦点移入，关闭时归还触发点；背景不可误操作。
- 状态与错误变化必须能被读屏感知；错误出现时移动焦点或使用可访问通知，不只改一段文本。
- 支持 200% 缩放和窄窗口重排。内容区可滚动，操作行固定在底部，不因缩放把按钮挤出屏幕。
- 对比度达到 WCAG AA；任何用颜色表达的状态都同时有文字、图标或形状。
- 尊重减少动态效果设置；不使用阻塞性、装饰性或自动播放动效。
- Android 触控目标不小于 44×44dp；桌面端点击目标不小于 24×24px，相邻目标不重叠。

## 8. 视觉基础

### 平台与现状

- **Windows**：JavaFX，暖纸色浅色主题（`desktop/src/main/resources/itemsync.css`），系统字体；主窗口使用“顶部应用栏 + 横向同步组标签 + 两栏工作台 + 底部状态栏”的壳层，中央可滚动。
- **Android**：程序化 View，`Theme.ItemSync`（暖纸/墨色/铜色，无 ActionBar），20dp 屏幕边距、16dp 卡片/弹窗边距；主屏为“品牌栏 + 横向同步组标签 + 状态卡 + 操作行 + 连接设置/身份卡”，并处理 Android 15 边到边 insets。正文 14–16sp，触控目标不小于 44dp。
- **CLI**：共用同一套术语与诚实语气；输出优先结构化、可管道处理。

### 方向与颜色角色

方向名：**信号台（signal desk）**。暖纸表面、墨色文字、铜色选择与焦点、细分隔线；没有渐变、没有装饰性阴影、没有玻璃拟态。

| 角色      | 值        | 用途                                         |
|-----------|-----------|----------------------------------------------|
| 画布      | `#F4F1EA` | 窗口底色                                     |
| 表面      | `#FBFAF6` | 应用栏、状态带、侧栏、对话框                 |
| 墨色      | `#171B1E` | 主文字、主按钮底色                           |
| 次要文字  | `#5E666B` | 标签、说明、eyebrow                          |
| 铜色      | `#B45309` | 选择、焦点、进行中状态；保持稀有             |
| 分隔线    | `#D9D3C7` | 壳层分区、输入框边框；优先用留白，其次才用线 |
| 在线/成功 | `#0F766E` | 已完成状态点                                 |
| 警告      | `#B54708` | 未解决冲突、需要注意但不阻断                 |
| 错误      | `#B42318` | 失败、危险动作、不可逆提示                   |
| 空闲      | `#98A2A8` | 未运行、未连接状态点                         |

主操作使用墨色实心按钮，不使用彩色 CTA。状态色只用于点、边框和少量文字，并且始终配文字说明，不单独承担语义。Android 的小字号铜色文本使用加深值 `#8A4B08`，保证 14sp 文本的对比度。

### 间距与布局

- 采用 4px 基准的本地间距阶：8px 组件内/相邻，12px 字段与行，16px 区块内边距，20/24px 窗口边距；组间间距至少是组内的两倍。
- 同组元素间距小于组间间距；分组优先用留白和分隔线，不嵌套卡片。
- 文本容器不设固定高度；长路径、指纹、设备 ID 允许换行，不靠截断隐藏关键信息。
- 主窗口宽度优先保证横向组标签不折行、两栏工作台中的主栏可读；窄窗口让中央滚动，不横向溢出。侧栏固定约 264px，最小 232px。

### 字体

- 系统 sans。Windows 中文回退到 Microsoft YaHei UI，托盘菜单显式选择该字体；Android 使用系统 sans。
- 桌面层级：10/11px eyebrow 与分区标题、12px 数据值、13px 正文、17px 品牌标题、28px 当前组状态；主层级依靠 13→28 的步长，微标签只用于辅助信息。
- 正文字号不低于 13px；Android 正文低于 14sp 视为缺口，不写入规范。
- 诊断值（组 ID、设备 ID、证书指纹、端口、计数）使用 `Consolas` 等宽字体，保证可对齐、可复制。

## 9. 组件与状态规则

- **主窗口**：顶部应用栏放品牌与一个主操作；其下是横向同步组标签、添加入口和组设置；中央是两栏工作台，左栏为状态带（组名、最近运行、冲突、错误）与“同步根/本机身份”数据，右栏为“操作/维护”侧栏；底部是状态栏，放产品定位与隐藏、退出。
- **按钮**：主操作是墨色实心键，次要操作是描边键，工具操作是无边框行；每个视图只有一个主按钮。危险按钮使用错误色文字并二次确认，不用大面积红色填充。禁用状态要有解释。
- **列表**：同步组、设备、冲突、版本使用列表或分栏；刷新时保留选中项；多行单元格允许换行；空列表要在原位说明下一步，不再弹第二个空状态窗口。
- **表单**：标签在控件上方或左侧并建立关联；提交时就地显示错误；不通过禁用提交按钮隐藏待修字段。
- **对话框**：内容可滚动，操作行固定；默认按钮是安全动作；破坏性动作二次确认，确认按钮写具体动词。
- **状态**：人类可读摘要加时间；原始 JSON、错误码和堆栈只进 tooltip、日志或诊断包。
- **加载**：写清正在做什么（扫描中、传输中、应用中），可测进度就显示进度，并提供取消入口（长任务）。
- **空状态**：说明这里属于什么、为什么重要、点击什么填充它。
- **溢出**：长路径与指纹换行或提供完整值入口；不出现横向滚动条作为主窗口的常态。

## 10. 组合默认

每个屏幕只选一个主导工作模式：

- **Operate**（主窗口）：保留壳层，工具靠近对象，状态与反馈在同一视野。
- **Monitor**（运行状态、在线/信任状态）：最近运行、冲突数、错误、离线与新鲜度优先。
- **Configure**（首次设置、组设置、同步规则）：按后果分组，提交区始终可见，危险变更先说明代价。
- **Compare**（设备列表、冲突列表、版本历史）：稳定列宽、可扫读的行、清晰选中态；历史可用分栏主从。

允许的构图车道：持久壳层、主从分栏、严格网格、密集列表行、内联分组表单、历史双栏。不要回到居中 hero、重复卡片、胶囊按钮和装饰性背景。

## 11. 已知设计缺口

来自 `checkup-report.md` 与本次 redesign 的实际状态：

已在桌面端处理：首次设置、解锁、添加组、组设置与闹钟规则的表单标签和可访问名称；弹窗内容的滚动容器；同步进行中的进度指示与“同步中…”文案；破坏性操作的默认按钮与具体确认动词；状态区不再输出原始枚举或 JSON。

仍需后续处理：

- 动态状态与错误变化不会被读屏主动播报。
- 长任务有进度指示，但仍没有取消入口。
- 部分禁用按钮仍缺少就地原因说明。
- Android 端已完成视觉重设计（`Theme.ItemSync`、程序化主屏、弹窗样式、通知与启动图标），但未做真机验证；Robolectric 单元测试与 debug APK 构建通过，不能代替设备验证。
- 托盘菜单仍以鼠标右键为主入口；主窗口保留了等价操作。

## 12. 使用方式

- 视觉方向、组件规则、文案与可访问性判断以本文件为准。
- 与本文件冲突时，优先级为：用户当前明确要求 > `docs/glossary.md` 与 ADR > 本文件 > 通用设计习惯。
- 修改本文件前先确认；不要把它拆成多个文档。
